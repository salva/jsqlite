## Shared architecture and adaptation invariants

Retain exact clause/term provenance, outer-ON safety, BigInt prerequisite masks/logical estimates, immutable admissions/loops/paths and schema PhysicalIndex/KeyInfo identity; mutable levels own cursor, direction, continuation, null/deferred/reset state. SELECT projection and ORDER comparison are semantic owners, not caller-local reinterpretations. Forced unsafe access rejects atomically; fallback retains residuals. Prepared plans do not eagerly execute RHS or decode persistent trees; reset retains bindings and clears execution-owned state; error publication/cleanup remain shared. No public API, native backend, writes, eval, registration, scope or operator inputs change.

Ordinary TS objects/BigInt/async execution are representation adaptations. Existing ordered-register-list versus native Btree quadratic tradeoff remains disclosed in current guide/evidence; missing machinery is not browser necessity. This proposal adds no algorithm substitution or parallel evaluator. Avoid a second planner, fake literal SELECTs, host hash membership, broad global refactor and SQL-text special cases.
