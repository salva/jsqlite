## New observation constraining comparator design

Native ENABLE_STAT4 **and** noSTAT4 return successful ordered rows for every edge mutation, including `sample=X'FFFF'`. Current TS sample admission also succeeds. The first consumer must preserve these outcomes; exposing current strict RawRecordReader corruption as an unconditional prepare failure would regress admission. Packed comparison's errCode and zero compare return are not interchangeable with a thrown database error. Numeric serial branches and padded reads differ from general record decoding; the exact affected C producer/consumer needs translation, not a blanket catch-all swallowing genuine storage corruption. The eight zero padding bytes remain owned by sample, excluded from record n. Count-overflow native success does not imply arbitrary overflow normalization or corruption rejection.

## Required resource test obligations (no invented public sample budget)

Existing API maxPrivateBytes is execution-wide sorter/ephemeral memory. A connection/schema-owned sample budget remains a concrete parent interface decision, not a platform blocker. After approval consuming tests must: (1) force capacity overflow before count-array allocation; (2) fail/cancel/deadline after first count-group allocation and after one raw sample copy; (3) assert no graph cached/reservations retained and successful retry on same open handle; (4) exercise cached graph reuse with statements resetting/finalizing without losing samples; (5) close during/after failing load and confirm storage/sample ownership released; (6) inject comparison/extraction failure at first and later field/IN member, verify restored active counts and all-slot free on builder index change/OR exit. Resource accounting must cover count-array slots and n+8 copied bytes with progress checks per stat row and bounded copy/comparison chunk; no full index/table materialization or cap. These are precise consuming test obligations, not falsely runnable tests against a nonexistent budget API.
