# Bounded host-task decision — [[card:card-h-e]]

Decision before implementation: retain every existing VM/private/scalar-input/async Function/overflow checkpoint and work charge. Replace only the host wait primitive with one execution-owned scheduler: seven MessageChannel task turns then one explicit timer turn, resetting cadence on statement reset. No microtask-only yields. Allocate at most one channel/two ports per awaited yield; close both and detach handler before resolving. No retained ports across rows or failures. Missing/throwing MessageChannel falls back to a real timer.

Concrete adaptation rationale: [current red evidence](red.md) measures ~95% elapsed waiting in ~4.2ms nested browser timers. SQLite vdbe.c check_for_interrupt/nProgressLimit own interrupt/progress observation, not host task timing; vdbeapi/vdbeaux retain saved error, halt/reset/delete ordering. JS same-agent AbortSignal requires task delivery. MessageChannel task delivery avoids nested-timer latency, while explicit timer turns every eighth checkpoint prevent reliance on unspecified cross-task-source fairness. This sacrifices some throughput to timer opportunities; neither primitive promises hard real-time latency, background-tab timing or arbitrary synchronous scalar preemption. Seven is a bounded policy, not SQL-specific tuning. Existing synchronous scalar traversal checks remain synchronous; async input and json_pretty checkpoints share the scheduler. No native SQL algorithm substitution or work/plan changes.

Tests written first: task-scheduler.test.mjs currently fails with missing module. Resource/fallback/cadence tests cover absent and throwing channel and at most two live ports. Real-browser red reproducer will remain unchanged; adapted measurements use its exact public path and compare reports rather than weakening its red predicate. Browser controls and existing focused regression suites remain required before acceptance.
