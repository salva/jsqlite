# Wide compound native-first correction

## Source diagnosis

Pinned SQLite 3.53.4 `select.c:multiSelect`2987–3003 invents ORDER BY 1 and calls `multiSelectByMerge` for **every** unordered non-ALL compound. Ordinary table dispatch instead accumulated replace-in-ephemeral sets. With duplicate NULL/NOCASE rows, INTERSECT returned the last left representative (`a`) instead of the merge's first (`A`). The fix selects the existing shared full-key merge for non-ALL, preserving its operator/EOF/duplicate/copy-before-OFFSET ownership; it does not globally change ephemeral replacement. The obsolete table set-transition tail is removed. Other algorithm-specific ephemeral consumers are not changed.

A second native-first case exposed result COLLATE naming/provenance. `columnTypeImpl` switches on the result Expr op, not its lookup child: TK_COLLATE has no column type/origin. Resolver now retains child binding/collation for evaluation but produces expression name/null physical metadata. Parentheses remain transparent. No new evaluator/parser or exceptional algorithm substitution.
