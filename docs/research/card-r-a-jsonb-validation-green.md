## Branch comparison

* Entry validates header/extent and depth before payload. Literal NULL/TRUE/FALSE require total header+payload length1 (nonminimal literal header is not strict-valid even though admission flag4 accepts it). Primitive decoder is not tightened; admitted raw/header representation remains untouched.
* INT consumes optional minus then payload digits, returns offending byte+1. INT5 checks min size/sign/0/x-or-X then hex payload with native offset ordering. FLOAT/FLOAT5 track dot/exponent seen state and consume exponent sign before missing-digit offset. No Number/AtoF grammar is substituted, no decoded UTF-16 offset conversion on BLOBs.
* TEXT scans `jsonIsOk` byte classes; TEXTJ/TEXT5 translate quote/control, escaped character, unicode-four-hex and JSON5 unescape/line-bypass paths. `jsonbUnescapeLength` is the length/invalid-status projection of `jsonUnescapeOneChar`/`jsonBytesToBypass`: validation does not need a decoded character value. Native length-only `\x` branch and raw high/invalid UTF8 bytes are retained, not rejected by a host decoder. TEXTRAW is accepted as bytes.
* ARRAY validates each child header/extent against container end before recursing, propagates absolute offset unchanged. OBJECT checks each even-position label type before child grammar; unmatched final label returns container end+1. Depth failure returns reached header+1, at depth1001 for strict entry1; renderer still starts0.
* `jsonArgIsJsonb` retains outer type/size/literal admission and small ambiguous BLOB deep check, now at shared default depth1. `jsonValid` flag4 remains superficial after admission; flag8 uses the same strict validator as error-position. TEXT-BLOB fallback/flags1/2, NULL and private scalar-to-text handoff remain unchanged. Constructor BLOB-value admission uses the same shared validity adapter; decode/render/private merge buffer are separate owners and unchanged.

No algorithm substitution is introduced: ordinary recursive byte traversal and a length-only unescape projection are browser-safe translations. Existing controls remain at Function/VM admission and retained JSON callers; this synchronous inspection helper has no cooperative yield/charge interface (as before), so these tests do **not** establish per-byte cancellation/resource-accounting parity for inspection. Do not imply all JSON controls are newly complete. Deep/large and malformed cases are finite evidence, not exhaustive validation or fuzz compatibility.
